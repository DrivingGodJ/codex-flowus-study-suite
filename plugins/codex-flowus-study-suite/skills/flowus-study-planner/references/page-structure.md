# Study-plan page structure

Use this as a flexible default, not a forced template:

1. Learning goal and constraints
2. Main course or resource for each learning track
3. Alternatives grouped under toggles
4. Practice projects and milestones
5. Checklist with preserved checked states

## Block choices

- Use a heading for each track.
- Use one callout for the primary resource and explain why it is primary.
- Put alternatives in a clearly named toggle with a count.
- Use paragraphs for short rationale and prerequisites.
- Use `to_do` blocks for observable actions; preserve existing `checked` values.

## Existing pages

Prefer existing sections and toggles when their meaning matches. Do not add duplicates merely because an old local plan used different labels. When a structural change requires real deletion or reordering that the available CLI cannot perform safely, leave the remote content unchanged and report the limitation.
